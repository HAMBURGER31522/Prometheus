# 转写引擎横向实测（R5，PLAN §15.4.3）

- 日期：2026-09-27
- 机器：Windows 11；RTX 4060 Laptop GPU 8GB（驱动 560.94）。桌面程序（Edge、ZCode 等）常驻占用约 2GB 显存，这也是用户平时的真实状态。
- 脚本：`scripts/asr-bench/`；环境：`E:\tools\Prometheus-Desktop\asr-bench\`（用法见该目录的 `使用说明.md`）；原始输出：`acceptance-output/asr-bench/`（不提交）。

## 样本与参考

| 样本 | 视频 | 时长 | 参考答案 |
|---|---|---|---|

B 站的 CC 字幕需要登录才能获取，所以两段样本都取自 YouTube。中文样本是典型的 B 站知识区视频：语速快，夹有采访片段、屏幕文字和电影片段。

## 方法

- 每个引擎在单独的进程里运行。`nvidia-smi` 每 200ms 采样一次显存，「显存增量」= 峰值 − 空闲基线。
- **字错率（中文）**：转成简体，去掉标点和空白，英文字母转小写。两边都用 cn2an 把中文数字换算成阿拉伯数字后再比较，「7%」和「百分之七」不算错；写法差异造成的编辑数单独列在「数字写法差异」一栏。
- **词错率（英文）**：转小写，去掉标点和撇号（缩写不展开，所以 "I've" 对 "I have" 也记为错误，对所有引擎一视同仁）。
- 参考字幕里的 `(Laughter)`、`[Music]`、`（笑）` 这类声音标注会先删掉。
- **加载**：加载模型的时间。whisper 这一行还包括启动进程和语言检测；必剪这一行是转 mp3 加上传的时间。**识别**：加载之后的识别时间。**实时率** = 识别时间 ÷ 音频时长，越小越快。
- 各引擎的配置：

| 引擎 | 配置 |
|---|---|
| faster-whisper turbo | 直接调用软件现有的转写 worker（`prometheus.transcribe.local_whisper`）：large-v3-turbo，CUDA float16，自动检测语言，VAD，中文加初始提示「以下是普通话的句子。」 |
| Qwen3-ASR-1.7B | `qwen-asr` 0.0.6，bf16，自动检测语言；时间戳由 Qwen3-ForcedAligner-0.6B 生成（音频按 180 秒以内的静音点切块）。测了两种加载方式：**同时加载**（包的默认用法，两个模型一起放在显卡上）、**先后加载**（先识别、释放显存，再对齐） |
| FunASR | paraformer-zh + fsmn-vad + ct-punc（FunASR 1.4.16，CUDA）。这是中文模型，按计划在英文样本上也跑了一遍 |
| 必剪（云端） | 非官方接口，model_id 8；上传 16kHz 单声道 48kbps 的 mp3 |

## 典型识别错误（只列替换，数字已统一换算）

删除和插入大多出在字幕和实际语音不一致的地方，所以下面只摘录「听错」的地方。上下文里的「同1个」是数字统一换算后的写法。

- **faster-whisper**：管中窥豹 → 亏报；答卷 → 打卷；不乏 → 不发；三大巨头 → 剧头；neural science → neuroscience；I am Wonder Woman strong → on（观众齐声喊口号的片段）
- **Qwen3-ASR**：管中窥豹 → 观众亏爆；粉丝量 → 质量；个位数 → 各位数；主流 → 主要；Arctime → 阿灿；try and → trying to
- **FunASR**：和你分析 → 以析；这件小事 → 这些小事；做字幕 → 做自己。英文基本不可用：understanding of neuroscience → understantime neual fights；physical → if ysical ical
- **必剪**：剪映 → 简易；统计型 → 统计性；总是 → 只需；抠绿 → 扣绿；bursts → first；why → y

## 观察

1. **中文准确度差距很小，而且在误差范围内。** 字错率从低到高依次是必剪 5.99%、FunASR 7.46%、whisper 7.86%、Qwen3 9.10%。但每个引擎有 65%–77% 的错误是删除或插入，而且集中在相同的几处：字幕里写了屏幕上的字、一段英文电影对白，同时漏掉了一句口播的玩笑。只看「听错」的替换数，依次是必剪 62、whisper 87、Qwen3 100、FunASR 119。只有一段 13 分钟的样本，1–2 个百分点的差距不足以作结论。
2. **Qwen3-ASR 在这段样本上没有赢过 whisper。** 这和公开基准（WenetSpeech 等）的结论不同：公开基准以朗读和新闻为主，而这段样本是语速很快的口语。
3. **英文**：whisper 最好（2.78%），Qwen3 其次（3.50%），必剪 6.18%。FunASR 用的是中文模型，英文基本不可用（12.98%）；如果选它，英文视频必须改用别的引擎。
4. **速度**（13 分钟音频的识别时间）：必剪 5 秒，FunASR 7 秒，whisper 20–30 秒，Qwen3 先后加载 60–78 秒。Qwen3 同时加载时要 5–9 分钟：两个模型加起来超出了这张 8GB 显卡剩余的显存，驱动把数据挪到共享内存，速度慢了 5–7 倍。按实时率推算 3 小时的视频（**推算，未实测**）：whisper 约 7 分钟，FunASR 约 2 分钟，Qwen3 约 18 分钟。
5. **显存**：whisper 1.9GB，FunASR 3.5GB，Qwen3 先后加载时仍要 7GB（一次识别 5 个 180 秒的音频块）。在 8GB 显卡上 Qwen3 已经是满载，6GB 显卡的笔记本跑不动。
6. **标点**：必剪几乎没有标点（每 100 字 0.9 个，其他引擎约 8 个）。字幕、`字幕.txt`，以及交给精读 Agent 的转写稿都会是一整串没有断句的文字。
7. **时间戳**：whisper、FunASR、必剪直接给出句子级分段（中位 2 秒左右），软件可以直接用作字幕。Qwen3 给出的是逐字或逐词的时间，需要先按标点重新拼成句子；时间更精细，但要多写一段代码。
8. **体积**：换成 FunASR 或 Qwen3 都要额外带上 torch（4GB），安装后的总体积会是现在的 2–3 倍。

## 需要用户决定

计划书规定由用户看表后决定默认的本地引擎（E5）。可选方案：

| 方案 | 说明 |
|---|---|
| A. 保持 faster-whisper turbo | 已经集成并测过；英文最好；中文与其他本地引擎的差距在误差范围内；显存和体积最小 |
| B. 中文改用 FunASR，英文仍用 whisper | 本地中文略好一点、速度最快；但要多带 torch 和两套模型（约 +6GB），并按语言切换引擎 |
| C. 改用 Qwen3-ASR | 这次实测里更慢、显存更大、没有更准，体积最大，**不推荐** |

执行 agent 的建议：**A**。另外，云端的必剪（D-32）中文最准、最快，但标点问题需要在 R6 接入时处理，这一点另行讨论。

未测：计划书中「时间允许时加测」的 Fun-ASR-Nano 没有测。
