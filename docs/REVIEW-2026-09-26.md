# 代码审查记录（2026-09-26）

审查对象：执行 agent 交付到 `main` 的 `50f61c3`（M0–M8 完成、M5/M9 进行中）。
审查方式：通读计划书与决策记录、源码与提交历史，在本机重跑全部测试，并用真实后端 + 真实视频（`BV1yPb46xExH`，104 分钟）从接口提交任务，走一遍软件界面实际会走的路径。

## 架构

- 计划书规定思维导图、配图各有独立文件夹，现在 `mindmap.py`、`frames.py` 都在 `report/` 下；一次性模型调用 `one_shot.py` 也放在 `report/`，被分类、导图、设置三处共用。
- 导图的提示词拼装和重试循环写在 `tasks/stages.py` 里，编排代码和功能逻辑混在一起（第 3 号 bug 就出在这里）。
- 数据目录用 32 位十六进制 ID 命名条目文件夹，用户在资源管理器里认不出哪个是哪个视频。
- 前端样式合计 38 行（`app.css` 27 行 + `tokens.css` 11 行），界面基本没有设计。

## 做得好的地方

- vendor 修改（V1–V3）范围克制，都有测试，默认参数下行为不变（有基线夹具锁定）。
- 各模块文件都不大，没有出现 BiliSum 那种六千行的巨型文件。
- 鉴权、CORS、外链拦截、繁简转换、本地 GPU 转写都实现了，并有测试。
- Git 历史里没有密钥泄漏（只有测试占位值），仓库只有 3.7MB。
- 发现问题后如实记录在验收文档里（例如两个中转站都不支持多模态）。
