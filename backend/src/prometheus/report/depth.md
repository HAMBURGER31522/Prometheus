# 完整精读（本任务的附加规则）

standard.md 写明「用户明确要求的深度优先」。本任务的用户明确要求**完整精读**：本文件的要求优先于 standard.md 和 SKILL.md 里与它冲突的默认取舍；本文件没有提到的规则（忠于来源、来源绑定与时间、商业推广的识别与排除、措辞、图示与组件、页面约定、交付检查）全部照常执行。

## 读者：聪明但零基础的成年人

- 读者**看不到视频**，只读这份报告。报告必须能独立读懂，不用「如视频所示」「前面提到」代替内容本身。
- 读者很聪明，但**从没接触过这个领域**：不认识这里的术语，不知道这里的人名和书名，也不知道讲者默认大家都懂的背景。不要把读者当小孩，也不要跳步。
- 写完以后，会有人**只拿这份报告**回答视频**每 5 分钟 4 道题**。题目来自原话里的定义、论断、理由、例子、数字、人名书名、步骤、条件和经历。报告里找不到答案就算漏写，答得含糊就算没讲清。
- 所以目标是：来源里每一个有实质内容的点都写到，并且讲到读者真正懂。

## 每个要点按四步讲

1. **是什么**：先用一句话说清它的本质。先讲它是干什么用的，再讲它怎么运作。
2. **类比**：把它和读者生活里已经熟悉的东西联系起来（「就像……」），让读者先有一个抓手。
3. **展开**：一层一层补上细节，按下面「每类要点怎么算讲清楚」的清单写：原理、理由、条件、步骤、例子、数字的口径。
4. **所以呢**：它对读者意味着什么；它和前后的要点是什么关系（因果、对比、递进、前提）。

**什么时候算讲完**：读者读完这一段，能不看报告、用自己的话把这个要点复述给别人听，还能回答「为什么」。做不到就继续讲。宁可讲透、讲长，不要点到为止；篇幅随内容增长，没有上限。

类比、关系和对比，能画成图示、对照表、卡片或步骤的，优先画出来，文字再把图里每个部分讲清楚。

## 一个要点里的东西都不能丢

- **列举要全**：原文说「只影响两件事」「有三个方面」「分四步」，或者并列列出好几项的，每一项都写出来，可以编号；不能只写「主要是某某」。
- **原因要全**：原文给出的每一层原因都写出来，不能只留第一层。例如原文说「一是因为 A，二是上次提到了 B」，两层都要写。
- **具体名称照写**：原因、例子、论证里提到的具体对象——公式、定理、人物、作品、工具、地名——照原样写出，不换成「某个方程」「一本书」。
- **谁说的就是谁说的**：写成讲者或视频里人物「说」「认为」「主张」的，只能是视频里真有的话；你自己的归纳、推论和背景知识用编者口吻写（「换句话说」「也就是说」），不要借人物之口说出来。

## 术语在第一次出现的地方解释

- 术语、专有名词、人名、书名、缩写、外语词，**第一次出现时就在那句话里用一句白话解释**，例如「萃取（热水把咖啡粉里能溶解的物质泡出来的过程）」，或者紧跟一句「也就是……」。
- 需要讲原理、来历或背景的，再加一个「补充说明」框展开（写法见下文）。
- 后面的章节再用到它时，再带一句解释，不要只写「如前所述」。

1. 口头禅和填充词（「对吧」「然后」「这个这个」）；

5. 技术故障（卡顿、调试麦克风）。

## 每类要点怎么算讲清楚

- **定义、概念**：它是什么；一个例子；和相近概念有什么区别。
- **论断、观点**：结论是什么；理由是什么；在什么条件下成立。
- **步骤、操作**：先后顺序；前提；每一步具体做什么；常见错误和注意事项。
- **数字、数据**：数值和单位；口径；和什么比较。
- **例子、故事、经历**：发生了什么；说明了什么。
- **人名、书名、术语**：按原话写出；第一次出现时交代是谁、是什么。

## 补充说明：鼓励讲深、讲长、讲易懂

视频一笔带过、没有解释的术语、背景和原理，**鼓励你用自己的知识补充**：

- 可以讲深：专业定义、来龙去脉、原理和机制；
- 也可以讲得通俗：打个比方，或者换一个角度再讲一遍，帮读者真正看懂。

补充内容的写法：

- 放在 `<aside class="supplement"><p class="supplement-label">补充说明（非视频内容）</p><p>……</p></aside>` 里，紧跟在相关段落之后；
- 不写成讲者的话，不替视频下结论，不能和视频内容矛盾；拿不准的背景知识不要写；
- 补充说明不需要 `data-source-units`。

## 编者观点（非视频内容）

视频的说法有争议、值得商榷，或者你想给出自己的判断时，写一个单独的框，放在相关段落之后：

```html
<aside class="viewpoint"><p class="viewpoint-label">编者观点（非视频内容）</p>
<ul>
<li>一点判断和它的理由。<span class="confidence">置信度：中</span>
依据：<a href="https://…">来源名称</a></li>
</ul></aside>
```

- 分点写，篇幅不限；可以不同意视频，但要讲出理由。
- 每一点标置信度（高 / 中 / 低），并给出依据：来源名称和 URL。只写你确定存在、而且内容相关的页面（百科、官方文档、论文的 DOI 页等稳定地址）；来源名称写那个页面自己的标题（英文页面写英文标题），程序会逐个打开核实，靠它判断页面是否相关；打不开或不相关的链接会被删掉，置信度随之降一档。
- 正文里不写成讲者的意图或说法：「作者这样安排，正是为了……」这类编者自己的推测，只能放进这个框。
- 编者观点和补充说明不同：补充说明是帮助理解的背景知识，编者观点是你对有争议之处的判断。

## 图文结合照旧，图多一些

VRA 的组件（表格、卡片、对照、步骤、强调框、时间线、关系图）和图示规则全部照用。内容写全以后，更要靠结构把长内容组织得好读。开了配图时，照 figures.md 使用候选帧。

本机是 Windows，命令工具是 PowerShell：用 Python 画图时运行 `& $env:VIDEO_REPORT_PYTHON draw.py`（modes/standard.md 里的 `"$VIDEO_REPORT_PYTHON" draw.py` 是 bash 写法，PowerShell 运行不了）；脚本和中间文件只写在当前工作区。

**什么时候画图示**：按内容的形状来画，不按要点数，也不按章节数：

- 有先后顺序的步骤 → 步骤图；
- 两样或几样东西的对比 → 对照表；
- 因果、依赖、循环 → 关系图；
- 并列的几类 → 卡片；
- 数量上的明显差别 → 柱图；
- 抽象的概念 → 用类比画一张示意图。

**图文不重复**：图注只写画面或图里的关键信息，和正文互补；正文不把图里的内容再罗列一遍，而是写图里画不出的道理和例子。

## 示例（与本任务的视频无关）

差：压缩成一句，术语没解释，读者什么也答不上来。

> 讲者介绍了影响手冲咖啡味道的几个因素，建议多尝试。

好：每个因素都按四步讲到，术语当场解释，因素之间的关系也交代了。

> 讲者把手冲咖啡的味道归结为三个可以控制的变量。它们都在影响**萃取**（热水把咖啡粉里能溶解的物质泡出来的过程）：泡出来的太少，味道偏酸、偏淡；泡出来的太多，又苦又涩。可以把它想成泡茶：泡太短没味道，泡太久发苦。
>
> **水温**决定泡得多快。浅烘豆（烘焙时间短、颜色浅的豆子，质地硬、不容易泡开）用 92–96°C，深烘豆用 85–88°C；水太烫会把苦味物质也泡出来，太凉则酸味突出、甜感不足。所以喝到发苦，第一个可以试的是把水温降一点。
>
> **研磨粗细**决定接触面积：磨得越细，水和咖啡粉接触的面积越大，萃取越快，就像碎冰比整块冰化得快。喝起来发苦就调粗一格，发酸就调细一格。
>
> **粉水比**（咖啡粉和水的重量比）决定浓淡：常用 1:15，也就是 15 克粉配 225 毫升水；想要更浓就改成 1:13，但总时长要控制在 2 分 30 秒到 3 分钟之间。
>
> 三个变量互相牵制：调细研磨会让萃取变快，这时可以把水温降 1–2 度来平衡。所以调味道时一次只改一个变量，才知道是哪一个起了作用。
>
> <aside class="supplement"><p class="supplement-label">补充说明（非视频内容）</p><p>一般认为，咖啡粉里的可溶物有 18%–22% 被溶解出来时味道最平衡：少于这个范围叫萃取不足，多于这个范围叫过度萃取。专业店会用折射仪测咖啡液的浓度，再反推萃取了多少。</p></aside>
